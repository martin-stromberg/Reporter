## Hinweise

- **`CardPositionText`-Nenner kann nach Einzelmarkierung + `LoadMore` minimal über der tatsächlich erreichbaren Stapelgröße liegen:** Beispiel — Paket mit 25 Artikeln, Seite 0 geladen (20), Nutzer markiert 1 Artikel als gelesen → DB-Rest 24, `_packetUnreadCount` = 24; `LoadMore` (`Skip(20)`) überspringt zusätzlich den ersten Artikel hinter der alten Fensterkante → nur 23 Karten erreichbar, Nenner zeigt „von 24". Das ist eine Folge des bestehenden Offset-Paging-Verhaltens bei Entfernen (bereits heute vorhanden, nur jetzt am Paket-Nenner sichtbar) und auf die Zahl einzeln entfernter Artikel begrenzt. Kein Blocker — der Nenner beschreibt weiterhin die in der DB verbleibenden Paket-Artikel korrekt (dieselbe Zahl, die „Alles gelesen" markiert). Empfehlung: im Test `CardPositionText_UsesPacketTotalAsDenominator` nicht auf strikte „erreichbare Positionen"-Semantik asserten bzw. die Ungenauigkeit im Getter-Kommentar dokumentieren.
- **Dialog-Format mit undatiertem Paket:** Das Format „{0} ungelesene Artikel vom {1}" erzeugt bei rein undatiertem Paket den Text „… ungelesene Artikel vom ohne Datum" — sprachlich holprig. Bei Bedarf ein alternatives Format für `IncludeUndated`-Pakete ohne datierte Tage erwägen (z. B. „{0} ungelesene Artikel ohne Datum"); die Implementierung sollte die Formulierung endgültig festlegen, `MarkAllReadConfirmationText_ComposesDayLabel` assertet derzeit nur die Label-Bestandteile.
- **`_packetDayLabel` bleibt nach Einzelmarkierung unverändert:** Werden alle Artikel des Anker-Tags einzeln als gelesen markiert (Folgetag-Artikel verbleiben), nennt der Dialog weiterhin beide Tage. Das ist konsistent zum unveränderten `_currentPacket` (der Markierbereich stimmt weiterhin) — lediglich eine kosmetische Ungenauigkeit, die bewusst hingenommen werden kann, da `MarkReadAsync` ausdrücklich keine Paket-Neubewertung auslösen darf.
- **Auto-Reload-Spezialfall bei Paket >`PageSize`:** Entfällt der letzte *geladene* sichtbare Artikel, obwohl das Paket noch ungeladene Artikel enthält, re-ankert `LoadAsync` auf demselben Tag — das Restpaket erscheint erneut. Folgt korrekt aus der definierten „frisches Laden"-Semantik (kein Überspringen), kann in `MarkReadCommand_EmptyingList_LoadsNextPacket` ggf. als zweite Seed-Variante mitbelegt werden.
