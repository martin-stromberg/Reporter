## Hinweise

- **Kleine interne Inkonsistenz (nicht blockierend):** Der Risiken-Abschnitt sagt „die Gates setzen explizit `IncludeAndroidTarget: false`", während der Änderungsabschnitt zu `staging-ci.yml`/`pr-staging-ci.yml` die Gate-Schritte als „unverändert" beschreibt und die Tasks keinen eigenen Eintrag für das Env-Flag enthalten. Da der Property-Default `false` ist, funktional unerheblich — bei der Umsetzung sollte das Flag entweder explizit ergänzt oder die Aussage im Risikotext gestrichen werden.
- **`release-tag`-Input:** Nach Entfernen des Manifest-Schritts aus `build-and-package` wird der Input in der Action nicht mehr benötigt; der Plan lässt bewusst offen, ob er mit den Callern konsistent entfernt wird (Implementierungsdetail).
- **Coverage-Gate-Risiko:** Das 70-%-Gate wird mit der Reaktivierung wieder scharf; die aktuelle Line Coverage ist lokal unbekannt. Der Plan benennt das Risiko korrekt (nachbessern statt Schwelle senken) — im Rollout frühzeitig beobachten.
- **`gh api`-Berechtigung:** Schritt 10 setzt voraus, dass das Token des ausführenden Agenten Admin-Rechte für Branch-Protection besitzt; der Plan dokumentiert das Vorgehen zusätzlich, sodass ein Admin es im Fehlerfall manuell nachvollziehen kann.
