# Bestandsaufnahme: Demo-Feed beim ersten Start (Issue #96)

Analysiert wurden der App-Start-Pfad (`App.OnStart`, `MauiProgram`), das Persistenzmodell für Kategorien und Feeds (`ReporterDbContext`, Entities, Repositories, Domänenmodelle) sowie der Start-Abruf (`AutoRefreshService` → `FeedSyncService` → `NotificationService`) bezogen auf die Anforderung, bei erstmaligem Start eine Kategorie „News" mit dem Feed `https://www.apple.com/newsroom/rss-feed.rss` zu seeden.

## Zusammenfassung

- **Kein First-Run-Mechanismus vorhanden:** Es gibt im gesamten `src/`-Baum kein `VersionTracking`, kein `IsFirstLaunchEver`, keine „First-Run"-Logik und keinen Demo-/Seed-Service. Die einzige `HasData`-Seed-Zeile ist die Singleton-`settings`-Zeile (`ReporterDbContext.cs:152`). Die Erkennung des ersten Starts muss neu gebaut werden.
- **Persistenzpfad ist vollständig vorhanden:** `ICategoryRepository.AddAsync`/`GetAllAsync` und `IFeedRepository.AddAsync`/`GetByUrlAsync` decken das Anlegen und die Dublettenprüfung ab. `categories.name` hat einen Unique-Index (`ReporterDbContext.cs:81`, SQLite-Default-Kollation = case-sensitiv), `feeds.url` ebenfalls (`ReporterDbContext.cs:100`). Eine Kategorie „News" ließe sich nur über `GetAllAsync()` + Namensvergleich finden — es gibt kein `GetByNameAsync`.
- **Etablierter Einhängepunkt:** `App.OnStart` (`App.xaml.cs:36-100`) führt `MigrateAsync` aus und ruft danach fehlerisolierte Blöcke (`try/catch` + `Debug.WriteLine` + `IDebugLogService.LogAsync` mit `DebugLogCategory.Lifecycle`). Zusätzlich läuft `MauiProgram.ApplyPersistedLanguage` (`MauiProgram.cs:135-152`) bereits vor `OnStart` eine synchrone `context.Database.Migrate()` — relevant für eine migrationshistorie-basierte First-Start-Erkennung: In `App.OnStart` ist `__EFMigrationsHistory` dann bereits befüllt, die Erkennung müsste vor dem frühesten `Migrate`-Aufruf erfolgen.
- **Feed-Defaults:** Referenz-Implementierung ist `FeedsViewModel.TryPersistNewFeedAsync` (`FeedsViewModel.Search.cs:301-329`): `HealthStatus = FeedHealth.Ok`, `NotificationsEnabled = true`, `LastCheckedAt = null`, `FaviconUrl` via `IFeedIconService` (offline `null`). `FeedTitleFallback.GetFallbackTitle("https://www.apple.com/newsroom/rss-feed.rss")` ergäbe `"rss-feed.rss"`; `FeedSyncService.ResolveFeedTitle` (`FeedSyncService.cs:276-286`) ersetzt solche Platzhaltertitel beim ersten erfolgreichen Sync durch den Dokumenttitel.
- **Start-Abruf greift automatisch:** `AutoRefreshService.StartAsync` (`AutoRefreshService.cs:44-53`) löst bei `RefreshOnStartupEnabled` (Default `true`, `settings.refresh_on_startup_enabled` mit `HasDefaultValue(true)`) und `IsOnline` den Fire-and-Forget-`RunStartupSyncAsync` aus — ein geseedeter Feed würde also beim ersten Start direkt synchronisiert, inkl. Favicon-Nachzug (`FeedSyncService.cs:196`) und Benachrichtigungs-Pfad (`NotifyNewItemsAsync`, `FeedSyncService.cs:201-217`; `LocalNotificationService.IsSupported` ist nur auf iOS `true`).
- **E2E-Nebenwirkung bestätigt:** `ReporterAppFixture` startet `Reporter.exe` mit frischer Temp-DB (`REPORTER_DB_PATH`, `ReporterAppFixture.cs:52-59`); nur der Feed-Search-Endpunkt ist gestubbt (`REPORTER_FEEDSEARCH_ENDPOINT`). Ein Demo-Seed würde in E2E-Läufen eine zusätzliche Karte und echten Netzverkehr zu `apple.com` erzeugen.

**Test-Ausgangszustand:** `dotnet test src/Reporter.Tests` (Release, mit Coverage): **504 bestanden, 0 fehlgeschlagen, 0 übersprungen** (Exit-Code 0). `npm test` (Skript-Tests): **36 bestanden, 0 fehlgeschlagen** (Exit-Code 0). Die FlaUI-E2E-Suite (`src/Reporter.E2ETests`, 7 Smoke-Tests) wurde nicht ausgeführt — sie benötigt einen vorgebauten `Reporter.exe` (nicht vorhanden) und eine interaktive Windows-Desktop-Session. Details und Nachweise: [Tests](inventory/tests.md).
