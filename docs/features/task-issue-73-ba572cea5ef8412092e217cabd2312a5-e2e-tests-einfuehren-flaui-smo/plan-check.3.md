**Status:** Plan lückenhaft

Die beiden Lücken aus dem zweiten Lauf sind verifiziert geschlossen: (1) `FeedsPage.xaml` Z. 176/191 werden jetzt korrekt als `x:Reference`-`BindingContext.*`-Hops **innerhalb** des `Feeds`-`DataTemplate` (Item-Kontext `models:FeedListItem`, Z. 145–298 — im Repo verifiziert) beschrieben und bleiben unverändert Runtime-Bindings (Plan Z. 25, 123, 181; Tasks Z. 7/13) — die falsche `{Binding IsOnline}`-Ersetzung ist entfernt; (2) die Start-Tab-Vorbedingung ist gelöst: `SelectTab(localizedTabTitle)` ist als Arrange-Schritt in **allen** sieben Feeds-Tests verankert (Plan Z. 61, 199, 218–225; Tasks Z. 19–26), `AddFeedViaUiAsync` beginnt damit, `ResetUiState` nutzt denselben Helfer, und `AppStarts_FeedListRenders` trägt den Unread-Start-Tab explizit im Arrange (Plan Z. 219, 237). ## Fehlende oder unvollständige Testanforderungen

- [ ] Vorbedingung für `SmokeTests.Search_SiteUrl_DiscoversFeedViaLinkTag` (Akzeptanzkriterium „deterministische Antworten inkl. Autodiscovery-Pfad"): `FeedSearchService.SearchAsync` ruft `SearchDirectoryAsync` immer zuerst auf (FeedSearchService.cs Z. 74) und fällt nur bei leerem Ergebnis auf `DiscoverFeedsAsync` zurück (Z. 84–88). Der Plan spezifiziert `/directory` als statisch nicht-leere JSON-Antwort ohne Auswertung des `?url=`-Parameters (Plan Z. 44, 96; Tasks Z. 21) — mit dieser Spezifikation liefert die Directory-Suche auch für die `/site`-Query Treffer, Discovery läuft nie, und der Test kann kein `Discovered`-Ergebnis (`MatchKind.Discovered`, Z. 202/234) beobachten. Der Plan muss festlegen, dass der Stub `/directory` query-abhängig beantwortet — z. B. leeres Array oder 404, wenn `?url=` auf keinen bekannten Stub-Feed zeigt (Fehlerfall ist ebenfalls zulässig: `directoryFailed` allein wirft keine Exception, Z. 96–99) — damit die Site-Query tatsächlich in `DiscoverFeedsAsync` landet.

## Fehlende oder unvollständige Planbestandteile

- [ ] Query-Verhalten der Stub-Route `GET /directory` spezifizieren: Der Plan beschreibt nur „JSON-Array im feedsearch-Format, URLs zeigen auf den Stub selbst (dynamisch aus `BaseUrl`)". Damit der Discovery-Test funktioniert, muss die Route den `?url=`-Parameter auswerten und für unbekannte/nicht-Feed-Queries (insb. die `/site`-URL) ein leeres Array oder einen Fehlerstatus liefern — sonst terminiert `SearchAsync` immer im Directory-Zweig (FeedSearchService.cs Z. 74–88). Ergänzend empfiehlt sich, das Stub-Directory so zu gestalten, dass es nur für die bekannten Stub-Feed-URLs Treffer zurückgibt.
