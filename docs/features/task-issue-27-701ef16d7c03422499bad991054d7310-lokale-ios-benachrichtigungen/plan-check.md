## Hinweise

- **Kleinere Ungenauigkeit in „Betroffene bestehende Tests":** `FeedRepositoryTests.GetByIdAsync_NonExisting_ReturnsNull` (`FeedRepositoryTests.cs:113-119`) enthält keinen `new Feed`-Initializer — es ruft nur `GetByIdAsync(Guid.NewGuid())` auf und ist daher nicht anpassungspflichtig. Die Liste ist damit über- statt unter-vollständig; alle tatsächlich betroffenen Initializer (Zeilen 38, 60–61, 77, 80, 100, 128) sind genannt.
- **`SyncFeedAsync_FeedDisabled_NoNotifications`** wird in der E2E-Tabelle als konkreter Integrationstest benannt, fehlt aber in der Tabelle „Neue Tests" — bei der Umsetzung sicherstellen, dass der Test auch tatsächlich angelegt wird.
- **Scope-Erweiterung bewusst entschieden:** `Settings.NotificationSummaryEnabled` geht über die Anforderung hinaus (dort steht `Settings` „unverändert"), ist jedoch die dokumentierte Anwenderentscheidung zu Offener Frage 3 (Aggregation einstellbar) und vollständig durchgeplant inkl. Migration, UI und Tests.
- Verifizierte Seiteneffekte vollständig erfasst: sämtliche `new Feed { … }`-/`new Settings { … }`-Initializer des Core-Modells im Produktivcode (`FeedRepository.MapToModel`, `FeedSyncService.UpdateFeedHealthAsync`, `FeedsViewModel.SaveAsync` 2×, `SettingsRepository.MapToModel`, `SettingsViewModel.PersistAsync`, `ArticleDetailViewModel.cs:250`-Fallback) und in Tests (`FeedRepositoryTests`, `FeedSyncServiceTests.SeedFeedAsync` Zeile 41 + `CreateService`/`CreateFailingService` Zeilen 65/72 für die neue Konstruktor-Abhängigkeit, `FeedsViewModelTests` Zeile 46, `SettingsViewModelTests_Persist` 207/247/285/344, `SettingsViewModelTests_Load` 48/88, `SettingsRepositoryTests` 71/96/138, `RetentionCleanupServiceTests` 41, `AutoRefreshServiceTests` 41/55). `ReporterDbContextTests_Persistence` (Zeilen 33, 71), `TestDataSeeder`, `UnreadViewModelTests`, `ItemRepositoryTests`, `CategoriesViewModelTests`, `CategoryRepositoryTests` verwenden `Entities.Feed` (nicht-required) — korrekt als unverändert eingestuft. `ServiceCollectionTests` registriert nur Repositories — kein Bruch durch den neuen `FeedSyncService`-Konstruktorparameter.
- `ReporterDbContext.HasData(new Settings())` (`ReporterDbContext.cs:135`) betrifft die Entity (Default `false`), nicht das `required init`-Core-Modell — korrekt nicht als Bruchstelle gelistet; die Migration `AddSettingsNotificationSummary` benötigt den `UpdateData`-Eintrag (im Plan enthalten).
- Vorab nachgewiesene flaky Tests (`SettingsViewModelTests_Persist`, 2 Fälle) sind in `inventory/tests.md` dokumentiert; der Plan referenziert die Suite `dotnet test src/Reporter.Tests` als Abnahmekriterium — bei Nichtdeterminismus auf diese Dokumentation zurückgreifen.
